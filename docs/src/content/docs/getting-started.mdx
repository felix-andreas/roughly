R will happily run this function. It will even work — until the day `raw` is
`"unknown"`, and a report deep in production tries to add `1L` to a string:

```r
parse_count <- function(raw) {
  count <- 0L
  if (raw == "unknown") {
    count <- "?"
  }
  count + 1L
}
```

Roughly catches it the moment you type it, with no annotations, no setup beyond
installing the extension, and no changes to your code:

```text
error[type-error] expected a numeric value (`integer` or `double`), found `integer | character`
--> 6:3-6:8
|   count + 1L
```

That is the pitch in one example: **Roughly is a static type checker for R** — the
first one — wrapped in a fast, all-in-one toolchain written in Rust. It reads the
R you already have, infers what your code means, and tells you where it cannot
mean what you wrote.

## Catch bugs before you run

The checker infers types for ordinary R code (Hindley-Milner style, the same
family of inference behind ML and Rust), so unannotated code is checked for
real. Wrong argument types, missing arguments, calling a value that isn't a
function, using a maybe-`NULL` value without a guard — all caught statically:

```r
ratio <- function(numerator, denominator) {
  numerator / denominator
}

ratio(1.0)
# error[type-error] This call passes 1 positional argument(s), but the function accepts 2.

total <- 10L
total(2L)
# error[type-error] expected function, found `integer`
```

And because the checker tracks variables through control flow the way R actually
treats them, it understands your guards too: `if (is.null(x)) return(0L)` narrows
`x` from `integer | NULL` to `integer` on the lines below.

## Types that live in comments

When you want to state intent — tighten an interface, document a function,
name a domain concept — annotations go in `#:` comments. Every other R tool
sees a comment; your code stays 100% ordinary R:

```r
#: fn(count: integer, label: character) -> character
render_row <- function(count, label) {
  paste0(label, ": ", count)
}

render_row("three", 3L)
# error[type-error] expected `integer`, found `character`
```

Adoption is gradual by design: inference-only checking works with zero
annotations, annotations tighten the parts you care about, and a strict mode
tells you what the checker could *not* see when you want the full guarantee.
The [typing guide](/typing) walks through the whole system.

## A real IDE for R

Roughly is a language server, so the checker's knowledge shows up as editor
intelligence in VS Code, Zed, or anything that speaks LSP:

- **Hover** any name for its inferred type and signature — including base R
  functions, which Roughly ships typed declarations for.
- **Completion** with real types: record fields after `$`, stdlib functions
  with signatures, annotation types inside `#:`.
- **Go-to-definition, find references, rename** — across files, aware of R's
  scoping, working on type names in annotations too.
- **Inlay hints and signature help** as you type.

## One style, zero debates

The formatter rewrites whole projects to one consistent style in milliseconds,
with `--check` and `--diff` modes for CI, and the linter catches the classics
(`=` vs `<-` assignment, `T` vs `TRUE`, misplaced commas) with stable codes you
can suppress line-by-line. Format-on-save works out of the box.

```bash
roughly fmt      # your whole project, one style
roughly check    # lint + type errors, machine-readable with --output json
```

## Built to scale

Roughly is written in Rust around an incremental analysis engine: it re-checks
only what an edit invalidates, so diagnostics and hover stay instant on
packages with hundreds of thousands of lines. The whole toolchain is one
binary with no dependency on an R session.

If a workspace ever feels slow, `roughly debug analysis-stats` prints a performance
diagnosis: per-phase timings for one full analysis pass (parse, lower, naming,
type checking, diagnostics), the slowest files with their line counts, and the
incremental cost of a single edit — the numbers to attach to a bug report.

## Try it

Install the [VS Code extension](https://marketplace.visualstudio.com/items?itemName=felix-andreas.roughly)
(everything bundled, nothing else to set up) — or see the
[installation page](/installation) for Zed, RStudio, the standalone CLI, and
CI setup.

Then, if you want the types:

```toml
# roughly.toml
[check]
typing = true
```
