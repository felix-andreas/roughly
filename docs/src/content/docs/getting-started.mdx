R will happily run this function. It will even work — until the day `raw` is
`"unknown"`, and a report deep in production tries to add `1L` to a string:

```r
parse_count <- function(raw) {
  count <- 0L
  if (raw == "unknown") {
    count <- "?"
  }
  count + 1L
}
```

Turn the type checker on — one line of configuration, no annotations and no
changes to your code — and Roughly catches it the moment you type it:

```toml
# roughly.toml
[check]
typing = true
```

```text
error[type-mismatch]: expected a numeric value (`integer` or `double`), found `integer | character`
 --> parse.R:6:3
6 |   count + 1L
      ^^^^^
```

**Roughly is modern developer tooling for R.** One binary, written in Rust: an
editor experience that actually understands your project, a type checker that
reads the R you already have, a formatter, and a linter. It needs no R
installation and no changes to your code.

What ties it together is the part the example above shows: Roughly works out
what your code *means*. Hover, completion, go-to-definition, rename and the
type errors are all built on that one piece of knowledge.

## Catch bugs before you run

You do not annotate anything to get this. Roughly works out what your code
means from how you use it — `a + b` makes `a` and `b` numbers, `paste0` makes
its arguments strings — so ordinary, unannotated R is checked for real. Wrong
argument types, missing arguments, calling a value that isn't a function, using
a maybe-`NULL` value without a guard: all caught statically.

```r
ratio <- function(numerator, denominator) {
  numerator / denominator
}

ratio(1.0)
# error[type-mismatch] this call supplies 1 argument, but the function requires 2
#                      — a required argument is missing

total <- 10L
total(2L)
# error[type-mismatch] this has type `integer`, which is not a function — it cannot be called
```

And because the checker tracks variables through control flow the way R actually
treats them, it understands your guards too: `if (is.null(x)) return(0L)` narrows
`x` from `integer | NULL` to `integer` on the lines below.

## Types that live in comments

When you want to state intent — tighten an interface, document a function,
name a domain concept — annotations go in `#:` comments. Every other R tool
sees a comment; your code stays 100% ordinary R:

```r
#: fn(count: integer, label: character) -> character
render_row <- function(count, label) {
  paste0(label, ": ", count)
}

render_row("three", 3L)
# error[type-mismatch] expected `integer`, found `character`
```

Adoption is gradual by design: inference-only checking works with zero
annotations, annotations tighten the parts you care about, and a strict mode
tells you what the checker could *not* see when you want the full guarantee.
The [typing guide](/typing/guide) walks through the whole system.

## A real IDE for R

Roughly is a language server, so the checker's knowledge shows up as editor
intelligence in VS Code, Zed, or anything that speaks LSP:

- **Hover** any name for its inferred type and signature — including base R
  functions, which Roughly ships typed declarations for.
- **Completion** with real types: record fields after `$`, stdlib functions
  with signatures, annotation types inside `#:`.
- **Go-to-definition, find references, rename** — across files, aware of R's
  scoping, working on type names in annotations too.
- **Inlay hints and signature help** as you type.

## One style, zero debates

The formatter rewrites whole projects to one consistent style in milliseconds,
with `--check` and `--diff` modes for CI, and the linter catches the classics
(`=` vs `<-` assignment, `T` vs `TRUE`, misplaced commas) with stable codes you
can suppress line-by-line. Format-on-save works out of the box.

```bash
roughly fmt      # your whole project, one style
roughly check    # lint + type errors, machine-readable with --output json
```

## Built to scale

Roughly is written in Rust around an incremental analysis engine: it re-checks
only what an edit invalidates, so diagnostics and hover stay instant on
packages with hundreds of thousands of lines. The whole toolchain is one
binary with no dependency on an R session.

## Try it

Install the [VS Code extension](https://marketplace.visualstudio.com/items?itemName=felix-andreas.roughly)
(everything bundled, nothing else to set up) — or see the
[installation page](/installation) for Zed, RStudio, the standalone CLI, and
CI setup.

Hover, completion and go-to-definition work immediately. Type *errors* are
opt-in, so add a `roughly.toml` next to your code when you want them:

```toml
# roughly.toml
[check]
typing = true
```

## Where Roughly looks

Roughly analyses `.R` and `.r` files. `roughly check` also reads **literate
documents** — `.Rmd`, `.qmd`, `.Rnw` — as the R program their chunks contain:
prose is ignored, a fence naming another language is skipped, and the whole
document is one script, so a chunk sees what earlier chunks defined. Inline
expressions count too — a value a report only displays as `` `r total` `` is used,
not unused, and a typo inside one is still reported. Every reported line and
column points at the original file. The formatter deliberately
leaves them alone (most of an `.Rmd` is prose it has no business rewriting), and
the editor integration does not cover them yet — `check` and CI do. `source()`
calls are not followed.

Files directly under a `R/` directory are **package source files**: they share
one namespace, so any one of them may call a function or reference a `#: @type`
name declared in another, and their top-level definitions are treated as
package-visible rather than unused. Files directly under `tests/testthat/` share
a namespace the same way, because testthat sources them into one environment —
`helper-*.R` first, then the tests — which is how a fixture is shared between
test files. Every other `.R` file — a driver script at
the project root, anything under `scripts/` or `inst/` — is a **script**: it is
analysed on its own, top to bottom, and its unused top-level bindings are
reported.

So a project laid out like this gets cross-file resolution for free:

```text
roughly.toml
R/load_data.R      # package source files: one shared namespace
R/summarise.R
run_analysis.R     # a script: analysed on its own
```

while the same files in a flat directory are each analysed in isolation, and a
call to a helper defined in a sibling file reports `unresolved`.
