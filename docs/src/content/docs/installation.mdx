Roughly runs as an editor extension (the comfortable way) or as a standalone CLI
(for scripts and CI). Pick whichever fits; they are the same binary underneath.

## VS Code (recommended)

[![](https://vsmarketplacebadges.dev/version-short/felix-andreas.roughly.svg)](https://marketplace.visualstudio.com/items?itemName=felix-andreas.roughly)

Install the [Roughly extension](https://marketplace.visualstudio.com/items?itemName=felix-andreas.roughly)
from the VS Code Marketplace. The extension bundles the Roughly CLI for **Linux x86_64, macOS aarch64,
and Windows x86_64**, so there is nothing else to set up.

> On another architecture, install the [CLI](#command-line) separately and point the extension at it
> with the `roughly.path` setting (see the [language server](/language-server) page).

## Zed

![Coming soon](https://img.shields.io/badge/Zed_registry-coming_soon-f4a15d?style=flat)

The Zed extension is not in Zed's extension registry yet. Until it lands there, install it from the
repository as a dev extension: install the [R extension](https://zed.dev/extensions/r) (Zed has no
built-in R support), then follow
[`editors/zed`](https://github.com/felix-andreas/roughly/tree/main/editors/zed) — three steps, and
the Roughly binary is fetched for you.

> To also get Roughly's `#:` annotation highlighting in Zed, enable LSP semantic tokens for R —
> see [the language server page](/language-server#annotation-highlighting-in-zed).

## Command line

Use the CLI directly for formatting and linting in CI, with RStudio, or to back an editor extension on
a platform without a bundled binary. Install it in whichever way suits you — a prebuilt binary, or from
source with Cargo.

**Prebuilt binary** (Linux, macOS, and Windows):

<Steps>

1. Download the binary for your platform from the [GitHub Releases](https://github.com/felix-andreas/roughly/releases) page.
2. Add it to your system `PATH`.

</Steps>

**With Cargo**, if you have a [Rust toolchain](https://www.rust-lang.org/tools/install):

```bash
cargo install --git https://github.com/felix-andreas/roughly roughly
```

## RStudio (formatter only)

You can configure Roughly as an external formatter in RStudio:

<Steps>

1. Open RStudio and navigate to:
   ```
   Options > Code > Formatting > Format with an External Tool
   ```

   Set the reformat command to: `path/to/roughly fmt`

2. To enable **format-on-save**, go to:
   ```
   Options > Code > Saving > Format with an External Tool
   ```

   Check the `Reformat documents on save` option.

</Steps>

## Usage

Three commands cover everyday use:

```bash
# Format R files (rewrites in place)
roughly fmt                # format files in the current directory
roughly fmt path/to/files  # format files at a specific path
roughly fmt --check        # list files that would change, exit 1 (for CI)
roughly fmt --diff         # show the diff without writing

# Lint and type-check
roughly check              # check files in the current directory
roughly check path/to/files
roughly check --output json  # one JSON object per diagnostic (for CI)
roughly check --min-severity error  # only errors render and affect the exit code

# Run the language server (for editors that speak LSP)
roughly server
```

Two more embed a real R session, for when you want to *run* the code rather than analyse it.
They locate R at runtime (`R_HOME`, or `R` on your `PATH`) — everything above needs no R at all:

```bash
roughly repl               # an interactive R console
roughly run script.R       # run a file; a top-level error exits non-zero
```

`roughly debug` holds development commands and is not part of the stable surface.

`roughly check` runs the linter and reports **unused bindings** with no configuration at all.
**Type errors** are the one thing you opt into, through `roughly.toml`:

```toml
[check]
typing = true   # report type errors
unused = false  # on by default — set this to silence unused-binding warnings
```

Type *inference* itself is always on and powers editor features like hover and inlay hints — the
settings above only control which diagnostics `roughly check` reports.

### Exit codes

`roughly check` and `roughly fmt` share one scheme:

| Code | Meaning |
| ---- | ------- |
| 0 | Clean — no diagnostics (`check`); nothing to change (`fmt`). A target with no R in it at all is clean, not a usage error: a stage with nothing to do must not fail a pipeline, and a pre-commit hook handing `fmt` a literate document it deliberately skips must not fail the commit |
| 1 | Findings — any diagnostic, warnings included (`check`); files that would be reformatted (`fmt --check`, `fmt --diff`) |
| 2 | Usage, configuration, or I/O error |

A warnings-only `check` run exits 1 by default; pass `--min-severity error` to gate on errors only.

### JSON output

`roughly check --output json` writes **JSON Lines** to stdout — one object per diagnostic, nothing
else, so the stream stays parseable while human-readable progress goes to stderr:

```json
{"code":"type-mismatch","column":1,"endColumn":2,"endLine":2,"line":2,"message":"this call passes 2 positional arguments, but the function only takes 1","path":"/home/you/project/R/config.R","related":[],"severity":"error"}
```

| Field | Meaning |
| ----- | ------- |
| `path` | Absolute path of the file |
| `line`, `column` | 1-based start position; the column counts **characters**, the same number the rendered output and your editor show |
| `endLine`, `endColumn` | 1-based end position, exclusive, columns in characters |
| `severity` | `"error"` or `"warning"` |
| `code` | The stable diagnostic code, the same one `# roughly: allow(...)` takes |
| `message` | The rendered message |
| `related` | Other locations the finding refers to — the same five position and message fields, one object each. Empty for most findings; a `duplicate` names both sites |

The summary line `check` prints at the end goes to stdout too, but only in human mode — a JSON run
emits nothing but diagnostics. These field names are a contract, safe to build CI on.

## Continuous integration

Roughly is one binary with no R dependency, so a CI job is a download and two commands. Both
`check` and `fmt --check` exit 1 on findings, which is what fails the job:

```yaml
# .github/workflows/roughly.yml
name: roughly
on: [push, pull_request]

jobs:
  roughly:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - name: Install Roughly
        run: cargo install --git https://github.com/felix-andreas/roughly roughly
      - name: Check
        run: roughly check
      - name: Format
        run: roughly fmt --check
```

To skip the build, download the binary for the runner's platform from the
[Releases](https://github.com/felix-andreas/roughly/releases) page and put it on the `PATH`
instead — nothing else about the job changes.

Two adjustments worth knowing:

- **Warnings fail the build by default.** A warnings-only run still exits 1. Pass
  `--min-severity error` to gate on errors alone while you work through a backlog of warnings.
- **`--output json` gives one JSON object per diagnostic** on stdout, with progress on stderr, if
  you want to post findings somewhere rather than read the log.
