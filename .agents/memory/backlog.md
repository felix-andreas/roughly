# Backlog — Beta program

**Goal:** bring the branch to **beta quality**. The previous alpha punch-list is superseded; this list is the result of a full adversarial audit (type checker core, LSP surface, formatter, config, stubs, engine) with every finding verified empirically before being recorded.

**Beta bar (acceptance):**
- **Sound on idiomatic R:** no known accepts-then-crashes holes on supported constructs; unsupported constructs may be refused loudly (sound-by-refusal is acceptable) but never silently mistyped.
- **Zero false positives on the ~200 most-used base functions** with `[check] typing = true` on idiomatic call forms.
- **Strict mode usable end-to-end** (discoverable config, per-file toggle, fires on real gaps).
- **Annotation UX complete:** formatting, hover, goto-definition, rename/references, highlighting work in all annotation positions, not just compact refs.
- **No server-killing input** (no `unwrap` panics on protocol-legal messages).
- **Perf budgets gated in CI**, not aspirational.

**Sequencing (user-decided): semantics first.** Semantics changes rewrite fixture expectations project-wide; do Phases 1–2 before the polish phases so fixtures are re-blessed once. The independent track can interleave anytime.

## Phase 1 — Semantics core

Update `typing-reference.md` **first** for each item (contract-first), then implement. Settled design rationale: `decisions.md` §Beta-semantics.

- **Multi-member unions** — **DONE.** Surface + core `A | B | C` everywhere a type may appear; normalization (flat, dedupe, `NULL` last, `Any`/`Unknown` absorb) lives solely in `union_of`; unification = set equality + the one nullable member-wise case; member-wise direction lives in compatibility; `if`/`else` joins branches (unify-or-union, `NULL` joins by pure union), `for`/`[` handle fixed-shape lists via the union element type. Contract: `typing-reference.md` §Union types/compatibility/unification.
- **R variable model: function-scoped mutable slots** — **DONE** (bare-name `<-`/`=` only; `<<-`/`->`/replacement forms are the next two items). Naming resolves every write of a name in a frame to one slot with per-read reaching-write sets (`naming.rs` flow walk, loop fixed point); typecheck keys its environment by slot and joins at control-flow merges via `join_types` (env-undo-log snapshots, loop fixed point capped at 3 passes then widen-to-`Unknown`; function bodies now also isolate via the log instead of cloning the whole environment). Package top level keeps winner semantics; conditional top-level assigns get document slots but stay non-global. Unused rebuilt on the reaching sets under its own `unused` diagnostic code (assignment-site reporting; dead stores between writes now caught; the conditional-update and loop-accumulator false positives are gone) — this also delivered the Phase-3 "unused rebuilt on reaching definitions" core (parameters-lint + `DiagnosticTag::UNNECESSARY` still open there). Operators/`$`/`[[`/`[`/`for` accept union operands member-wise with joined results (the headline `x <- 1L; if (f) x <- "two"; x + 1L` now errors on `integer | character`). Contract: `typing-reference.md` §Value names / §Control-flow joins / §Operators over union operands. Follow-ups noted: goto-definition returns the slot's first write only (all-reaching-writes is a later refinement); flow-sensitive narrowing builds on this model (Phase-1 exit note).
- **`<<-`, `->`, `->>` lowering — DONE** (mirror assigns; `<<-` resolves outward, creates a document slot with a warning when nothing encloses; `break`/`next` are real HIR nodes and loops containing them join exit states with the pre-state; closure-captured slots join all frame writes; loop widening records a strict origin; the loop fixed point memoizes converged inner regions; the for variable stays visible after its loop).
- **Replacement-form assignment lowering — DONE** (read+write of the base variable, accessor spine fully visited; record-field updates via `$<-`/literal `[[<-` refine the slot's record type; replacement writes are exempt from unused reporting).
- **`@param name {TYPE}` syntax flip (user-decided, `decisions.md`):** parser, checker fixtures, formatter, typing-reference + guide, semantic-token classifier roles (the name token is currently classified TypeName in the old order), and the old order rejected with a targeted "write `@param name {type}`" error. Same re-bless wave as the coercion slice.
- **Coercion policy — DONE** (integer widens to double across all shapes in compatibility, directional only; whole-number double literals count as integer at parameter positions; contract updated). The corpus-side half — vectorized stubs declaring `T[]` parameters — lands with the Phase-2 corpus rewrite.
- **Name-aware signature matching — DONE** (annotation params align to formals by name, positional fill for unnamed; function-type compatibility pairs named params by name; renaming a parameter in an annotation is a dedicated error; contract rewritten).
- **Any/Unknown/inference-variable compatibility violations** (verified, spec-breaking): `c(...)` and `for` hard-reject `Any` (spec: compatible with everything) and cascade errors on `Unknown` (spec: never cascade); `c`/`$`/`[[`/`[`/`for` reject unannotated parameters with `expected integer, found T` (the wording now renders the variable as `T`; the rejection itself is still the bug). Give these constructs the same tolerate-Unknown/constrain-variable treatment arithmetic already has (structural constraints on inference variables: record-with-field, indexable, atomic-element).
- **Variadic `...` bridging — DONE.** R's `...` is a positioned rest parameter end to end: `RestParameter { element, preceding_named }` carries the formal position (formals before the dots fill positionally, formals after by name only — R's matching exactly); inference emits it with element `Any` (body uses of `...` stay `Unknown`); the annotation grammar accepts named parameters after `...` (rest no longer forced last; positional-after-rest is a targeted error); compatibility/unification require matching rest positions with contravariant elements, so variadic annotations on user functions now check; signature help translates matcher slots to the display order; stubs rewritten to R's true formal order. Contract: typing-reference §rest parameter / §Function calls / §Function type compatibility / §Inferred function types.
- **`m[i, j]` / `x[]` — DONE and verified in code:** the Unknown/Any short-circuit runs *before* the index-arity check (`infer_subset_expression`), and the error is indexing-specific (`UnsupportedIndexShape`: "indexing with N indexes is not supported yet — matrix and data.frame subsetting is not modeled"; `x[]` and named indexes get their own wording).
- **Shape erasure on comparison/`/`/`^` results — resolved as documented policy:** `function(x) x > 0L` types `fn(x: T) -> logical`; the scalar claim on a flexible operand is the same deliberate compromise the corpus applies to every elementwise function (scalar coerces into all vector positions — never a false error; vector-in/vector-out shape untracked), now stated in typing-reference §Arithmetic operators ("Shape of a flexible operand") with the `T[]`-bound exception, whose results are genuinely vector-shaped. True shape polymorphism (result shape tied to the operand's shape variable) is the post-beta upgrade path, same family as traits.
- **Recursion — investigated, needs real design, two distinct gaps:** (a) a *local* recursive function does not resolve at all — the closure RHS cannot see the slot the enclosing assignment is about to create (letrec: the naming walk must make an assignment's target slot visible inside its own RHS closures); today it is a loud unresolved-name warning, sound-by-refusal but wrong modeling. (b) a *top-level* recursive function resolves through the interface fixed point to a scheme that merely *contains* `Unknown` in return position, so no reference-site strict origin fires — silent; attribution needs the fixed point to record a strict origin on the binding whose exported scheme retains `Unknown` after convergence. A naive origin at the unbound-local-read fallback covers neither and double-reports maybe-undefined branch reads.
- **Order-dependent acceptance**: a successful `check_compatibility` commits unification of directional checks, so `{k(x); h(x)}` passes where `{h(x); k(x)}` errors. Probe-then-rollback for coercion-flavored checks; commit only equalities.
- Smaller verified spec/impl bugs to sweep in the same pass — one left: comparison of two flexible operands imposes no constraint (lists comparable; needs an atomic-comparison constraint — the recorded third-constraint-kind/traits tripwire, check in with the user first). (All other entries resolved: integer-vector arithmetic no longer pins a flexible operand to `double` (re-probed, fixed by the flexible-vector operator work); an applied type parameter is now an annotation error in both pipelines instead of resolving to the shadowed global; the hardcoded-`Pair` and integer-vector-pinning entries were re-probed and verified already fixed by earlier slices). (Resolved from this list: `Any[]` now means a vector with a statically untracked element, and `X[]` for any other non-atomic `X` is an annotation error pointing at `list[X]`; `$` on atomic vectors — named ones included — is now rejected with a dedicated error pointing at `[[`, matching R; `:` endpoints now carry the scalar-numeric bound, so vector endpoints through polymorphic calls are rejected; positional/computed `[[` on `list[named: T]` extracts `T`, mirroring the map-like-vector arm; the compat variable arms propagate `RecursionLimitExceeded` instead of swallowing it into `false`.)

- **`missing()`-guarded formals — cheap direction DONE:** a formal the body tests with `missing(name)` is optional at call sites (`hir::formals_tested_by_missing`, bare-callee recognition, nested function literals skipped since R's `missing` sees only the enclosing function's formals; annotations still win as the interface). The precise version is also DONE: `missing(x)` on a defaultless formal of the current frame narrows the slot's supplied state along the branch edges (`Binding.unsupplied` + per-edge flags on `GuardRefinement`; `InferenceState.missing_narrowable` holds the frame's defaultless parameter slots, saved/replaced per body). Reads on the unsupplied edge raise `InferenceError::MissingArgumentRead` (R-accurate wording); writes supply the slot; joins keep the flag only when both edges agree (definite-failure reporting); `!missing(x)` swaps edges; defaults are never narrowed. Needs a naming context, so the semantic fixtures live in the realworld suite (`config_options`); contract in typing-reference §function inference.
- **Union follow-ups (from adversarial review):** (a) the type grammar has no parenthesized groups, so a union with a function member — `(fn() -> integer) | NULL`, the idiomatic optional callback — is renderable but not *writable*; add paren grouping to `type_syntax`. (b) Compatibility's bind-variable-to-union fast path widens the known order-dependent-acceptance class: `{ g(x); h(x) }` vs `{ h(x); g(x) }` can differ when `g` expects a union and `h` a member (spec-permitted; revisit with member re-probe on later narrowing use).

## Phase 3 — Trust & UX (config, strict, lints, CLI)

- **Config subsystem rebuild** — core landed: the workspace root comes from `InitializeParams` (`workspace_folders`, then `root_uri`, cwd only when the client sends neither; the worker is constructed by the `Job::Initialize` handler so nothing reads config before the root is known); discovery is one nearest-ancestor search (`Config::discover`, target absolutized first) shared by the LSP (from the client root) and the CLI (from each target argument); unknown keys and type errors are errors with file + 1-based line:column (`deny_unknown_fields` on `ConfigToml`/`FormatConfig`/`CheckConfig`/`LintConfig`; `ConfigParseError` renders the toml span) — the server never panics on a malformed config (defaults at startup, previous config on reload, `window/showMessage` both times; the CLI prints the rendered error and exits non-zero); a successful reload refreshes diagnostics (push: republish open documents; pull: `workspace/diagnostic/refresh`; shared `refresh_all_diagnostics`). Still open:
  - Config collapse — DONE: `engine::queries::Config` now carries the analysis `CheckConfig`/`LintConfig` directly (the flat-flag mirror is gone); `ConfigToml` remains only as the thin serde wrapper for the legacy `case`/`spaces` aliases. Adding a `[check]`/`[lint]` key now touches the analysis struct and the docs.
  - Per-lint severity — DONE: `[lint]` keyed by stable code (`assignment-operator`/`boolean-shorthand`/`missing-comma`/`trailing-comma` take `"off" | "warn" | "error"`, default = built-in severity via `LintLevel::Default`; `naming-style` keeps its style value, omit = off).   - `workspace/didChangeConfiguration` — DONE (rejects loudly: a non-empty settings payload triggers a one-time notice that configuration lives in `roughly.toml`; the notification itself stays accepted for Zed).

- **Single parse per edit — DONE:** the `SourceText` input now carries a `ParsedDocument` (rope-equality is the cutoff, as before); the server feeds its incrementally-maintained open-buffer `Document` on every keystroke (no whole-buffer `String` re-materialization, no second parse — `set_parsed_input`), disk loads parse once, the `Parse` query is a projection with the tombstone degrading to an empty parse, and test drivers go through `queries::parse_source_input`.

- **Relative perf evidence (dev container, non-authoritative absolutes):** after the per-file exports query + template clone + single lower, per-edit recompute stays at 2 queries and the new-vs-old ratio improved ~10.6×→~131× at 281k LoC — but the absolute per-edit time on the same box rose versus the pre-semantics baseline (the slot-model flow walks, union normalization, and loop fixed points made whole-file inference genuinely more expensive). A known-field write on an empty `list()` starts a record (`list{field: V}`); a computed-key `[[<-` makes an empty `list()` map-like (`list[named: V]`), joins into an existing `list[named: T]`/`list[T]` element, and leaves records and fixed-shape tuples unchanged (no precision loss, no record→map widening). A `character | NULL`-*typed* value flows fine — only the bare literal misfires. Fixing it needs argument-order-independent generic instantiation (defer each type parameter's binding until all arguments are seen, then join), which is a larger inference change; recorded here rather than worked around.
