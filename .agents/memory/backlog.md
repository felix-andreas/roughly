# Backlog — Beta program

**Goal:** bring the branch to **beta quality**. The previous alpha punch-list is superseded; this list is the result of a full adversarial audit (type checker core, LSP surface, formatter, config, stubs, engine) with every finding verified empirically before being recorded.

**Beta bar (acceptance):**
- **Sound on idiomatic R:** no known accepts-then-crashes holes on supported constructs; unsupported constructs may be refused loudly (sound-by-refusal is acceptable) but never silently mistyped.
- **Zero false positives on the ~200 most-used base functions** with `[check] typing = true` on idiomatic call forms.
- **Strict mode usable end-to-end** (discoverable config, per-file toggle, fires on real gaps).
- **Annotation UX complete:** formatting, hover, goto-definition, rename/references, highlighting work in all annotation positions, not just compact refs.
- **No server-killing input** (no `unwrap` panics on protocol-legal messages).
- **Perf budgets gated in CI**, not aspirational.

**Sequencing (user-decided): semantics first.** Semantics changes rewrite fixture expectations project-wide; do Phases 1–2 before the polish phases so fixtures are re-blessed once. The independent track can interleave anytime.

## Phase 1 — Semantics core

Update `typing-reference.md` **first** for each item (contract-first), then implement. Settled design rationale: `decisions.md` §Beta-semantics.

- **Multi-member unions** — **DONE.** Surface + core `A | B | C` everywhere a type may appear; normalization (flat, dedupe, `NULL` last, `Any`/`Unknown` absorb) lives solely in `union_of`; unification = set equality + the one nullable member-wise case; member-wise direction lives in compatibility; `if`/`else` joins branches (unify-or-union, `NULL` joins by pure union), `for`/`[` handle fixed-shape lists via the union element type. Contract: `typing-reference.md` §Union types/compatibility/unification.
- **R variable model: function-scoped mutable slots** — **DONE** (bare-name `<-`/`=` only; `<<-`/`->`/replacement forms are the next two items). Naming resolves every write of a name in a frame to one slot with per-read reaching-write sets (`naming.rs` flow walk, loop fixed point); typecheck keys its environment by slot and joins at control-flow merges via `join_types` (env-undo-log snapshots, loop fixed point capped at 3 passes then widen-to-`Unknown`; function bodies now also isolate via the log instead of cloning the whole environment). Package top level keeps winner semantics; conditional top-level assigns get document slots but stay non-global. Unused rebuilt on the reaching sets under its own `unused` diagnostic code (assignment-site reporting; dead stores between writes now caught; the conditional-update and loop-accumulator false positives are gone) — this also delivered the Phase-3 "unused rebuilt on reaching definitions" core (parameters-lint + `DiagnosticTag::UNNECESSARY` still open there). Operators/`$`/`[[`/`[`/`for` accept union operands member-wise with joined results (the headline `x <- 1L; if (f) x <- "two"; x + 1L` now errors on `integer | character`). Contract: `typing-reference.md` §Value names / §Control-flow joins / §Operators over union operands. Follow-ups noted: goto-definition returns the slot's first write only (all-reaching-writes is a later refinement); flow-sensitive narrowing builds on this model (Phase-1 exit note).
- **`<<-`, `->`, `->>` lowering — DONE** (mirror assigns; `<<-` resolves outward, creates a document slot with a warning when nothing encloses; `break`/`next` are real HIR nodes and loops containing them join exit states with the pre-state; closure-captured slots join all frame writes; loop widening records a strict origin; the loop fixed point memoizes converged inner regions; the for variable stays visible after its loop).
- **Replacement-form assignment lowering — DONE** (read+write of the base variable, accessor spine fully visited; record-field updates via `$<-`/literal `[[<-` refine the slot's record type; replacement writes are exempt from unused reporting).
- **`@param name {TYPE}` syntax flip (user-decided, `decisions.md`):** parser, checker fixtures, formatter, typing-reference + guide, semantic-token classifier roles (the name token is currently classified TypeName in the old order), and the old order rejected with a targeted "write `@param name {type}`" error. Same re-bless wave as the coercion slice.
- **Coercion policy — DONE** (integer widens to double across all shapes in compatibility, directional only; whole-number double literals count as integer at parameter positions; contract updated). The corpus-side half — vectorized stubs declaring `T[]` parameters — lands with the Phase-2 corpus rewrite.
- **Name-aware signature matching — DONE** (annotation params align to formals by name, positional fill for unnamed; function-type compatibility pairs named params by name; renaming a parameter in an annotation is a dedicated error; contract rewritten).
- **Any/Unknown/inference-variable compatibility violations** (verified, spec-breaking): `c(...)` and `for` hard-reject `Any` (spec: compatible with everything) and cascade errors on `Unknown` (spec: never cascade); `c`/`$`/`[[`/`[`/`for` reject unannotated parameters with `expected integer, found T` (the wording now renders the variable as `T`; the rejection itself is still the bug). Give these constructs the same tolerate-Unknown/constrain-variable treatment arithmetic already has (structural constraints on inference variables: record-with-field, indexable, atomic-element).
- **Variadic calls to locally-defined `function(x, ...)`** are hard arity errors (inference drops `...`). Bridge: make inference lower a trailing `...` parameter as a rest parameter (preferred over a compat special-case).
- **`m[i, j]` / `x[]`** (matrix/data.frame subsetting): unconditional arity error with call-wording, even when the subject is `Unknown`. Check the Unknown/Any short-circuit *before* arity; message must name indexing, not "this call".
- **Shape erasure on comparison/`/`/`^` results** (verified unsound): `function(x) x > 0L` typed `fn(x: T) -> logical` claims scalar; vector argument yields runtime `logical[]`. Result shape must depend on the operand's resolved shape (tie result shape to the constrained variable), or the scheme must not promise scalar.
- **Recursion — investigated, needs real design, two distinct gaps:** (a) a *local* recursive function does not resolve at all — the closure RHS cannot see the slot the enclosing assignment is about to create (letrec: the naming walk must make an assignment's target slot visible inside its own RHS closures); today it is a loud unresolved-name warning, sound-by-refusal but wrong modeling. (b) a *top-level* recursive function resolves through the interface fixed point to a scheme that merely *contains* `Unknown` in return position, so no reference-site strict origin fires — silent; attribution needs the fixed point to record a strict origin on the binding whose exported scheme retains `Unknown` after convergence. A naive origin at the unbound-local-read fallback covers neither and double-reports maybe-undefined branch reads.
- **Order-dependent acceptance**: a successful `check_compatibility` commits unification of directional checks, so `{k(x); h(x)}` passes where `{h(x); k(x)}` errors. Probe-then-rollback for coercion-flavored checks; commit only equalities.
- Smaller verified spec/impl bugs to sweep in the same pass: comparison of two flexible operands imposes no constraint (lists comparable); `$` accepted on atomic named vectors (runtime error; spec bug — `$` ≡ `[["name"]]` is defined unconditionally); `:` accepts vector endpoints through a polymorphic call (numeric constraint lacks scalar-ness); integer-vector arithmetic pins a flexible operand to `double` and then rejects integer callers; positional `[[` on `list[named: T]` rejected (R allows; map-like *vectors* accept — inconsistent); hardcoded `Pair` arity check in the parser hijacks user `Pair` (`type_syntax.rs` literal match); generic application `T<...>` inside a definition ignores parameter shadowing when arguments are present; `check_compatibility` variable arms swallow `RecursionLimitExceeded` into plain `false`. (Resolved from this list: `Any[]` now means a vector with a statically untracked element, and `X[]` for any other non-atomic `X` is an annotation error pointing at `list[X]`.)

- **Union follow-ups (from adversarial review):** (a) the type grammar has no parenthesized groups, so a union with a function member — `(fn() -> integer) | NULL`, the idiomatic optional callback — is renderable but not *writable*; add paren grouping to `type_syntax`. (b) Compatibility's bind-variable-to-union fast path widens the known order-dependent-acceptance class: `{ g(x); h(x) }` vs `{ h(x); g(x) }` can differ when `g` expects a union and `h` a member (spec-permitted; revisit with member re-probe on later narrowing use).

## Phase 4 — Editor polish (LSP + formatter)

LSP (all verified against code + probes):

- **Server robustness — DONE.** Protocol-legal input no longer kills the process. Non-`file:` URIs (untitled buffers) are *served* as standalone script documents: keyed by a synthetic path under the workspace root so the path-keyed host/engine tables track them, with `virtual_document_uris` mapping back to the client URI for outgoing locations and published diagnostics; a malformed `file:` URI is dropped with a warning. Range-less (full-text) `didChange` applies a whole-document replacement; `did_close`'s disk re-read tolerates a delete/rename race like the watcher path (failed read = deletion); non-file watcher events are skipped with a warning. `cancellable` now surfaces `Err(Cancelled)` and each read handler decides: pull diagnostics answers `ServerCancelled` + `retriggerRequest: true` (per spec, so the client re-pulls instead of caching an empty authoritative report; wire shape pinned by a `server.rs` unit test — the harness cannot trigger in-flight cancellation deterministically), rename answers `ContentModified` (a `null` edit would silently rename nothing), best-effort lookups (hover/completion/definition/references/inlay/symbols) still answer empty. Past-EOF LSP positions are clamped in `position.rs` (line to last line, column to line end), and the byte-as-code-unit range fallback for untracked files warns instead of degrading silently. Coherence policy unchanged: document-sync failures on tracked documents still panic (deterministic death via the worker loop).
- **Annotation cursor features, complete:** goto-def/hover work only in *expression-attached* annotations. Dead inside `@type`/`@alias` **definition bodies** (definition blocks never attach to an expression, so `annotation_range_at` never sees them — the most common place for type refs) and inside **generic arguments** (`Wrapper<Person>`: every `<` bumps binder depth, so args classify as `TypeParameter`). References/rename have no type-name path at all — aliases are un-renameable. `@param name {T}` classifies `name` as TypeName (miscolor + wrong-jump). Cursor at a token's right edge misses (end-exclusive containment) — affects plain identifiers too.
- **Completion:** dead while typing after a single `:` (`1:n` — `MaybeNamespace` never resets); **no stdlib completions** (the corpus feeds hover but not completion); no top-level bindings in scripts; `$` completion ignores the type checker (typed record fields are the flagship completion for this product; user-confirmed priority) — and the same typed-field source must serve string-content completion inside `[["..."]]`: a completion position inside a string literal that is the `[[` argument on a record-typed subject offers the field names as string contents (add `"` as a trigger character); no type-name completion inside `#:`; items lack detail/documentation/snippets.
- **First code actions** (today: zero, no provider registered): remove unused assignment; prefix with `.`; insert inferred type annotation (inlay-hint machinery already computes the text); `@if-unknown`→`@trust` fix; typo-suggestion for unresolved names.
- Cheap wins with existing machinery: document highlights (references machinery exists); goto-type-definition (checked type → `@type` decl); folding ranges; prepareRename + new-name validation (rename to `my var` currently produces broken R silently); `@type`/`@alias` + `=`/`<<-` bindings in the outline; workspace symbols shouldn't re-walk every package file per keystroke, and should include open scripts.
- **`.Rtypes` served as documents — parse diagnostics DONE** (stub buffers live entirely server-side against a throwaway interner; the engine's set-once stub input is untouched; push-published on open/edit). Still open: semantic tokens + goto-def for stub buffers, and pull-diagnostics reports for them (push works for pull clients but a dedicated report is cleaner).
- **Numeric constraints vanish from hover/inlay/signature display:** `function(x) x + 1L` hovers as `<T> fn(x: T) -> T`, not `<T: numeric> …` — the IDE layer stores checked expression types as `CoreType` (constraints live in the inference state / `TypeScheme` only), so display-time generalization quantifies unconstrained. Interface/scheme renderings show the constraint correctly. Fix needs typecheck to expose constraints alongside stored expression types (or store schemes for binding reads).
- **`#:` highlighting in Zed + VS Code fallback — DONE.** The "Zed does not consume LSP semantic tokens" premise is outdated: Zed consumes them opt-in (`"semantic_tokens": "combined"`, global or per-language), and its built-in default rules style all five token types the server emits; the Zed setup (R-extension prerequisite + the setting) is documented on the language-server docs page. Shipping tree-sitter queries from our Zed extension is not possible without owning the R language (the community R extension owns it; a Zed extension cannot extend another extension's queries), and owning it would mean vendoring full R highlighting — rejected. VS Code: a TextMate injection grammar into `source.r` (`editors/code/r-annotation.tmLanguage.json`, scopes mirror the server's classifier, validated with vscode-textmate against VS Code's built-in R grammar) covers semantic-tokens-off contexts and colors punctuation the tokens skip (`|`, brackets, commas); `decorator` is themed by VS Code's defaults (probes `entity.name.decorator` → `entity.name.function`), so no `semanticTokenScopes` contribution is needed. Follow-ups: upstream a `#:` comment injection to the community Zed R extension for default-on highlighting; emit the `declaration` modifier on `parameter` tokens so Zed's default rules style them `variable.parameter` instead of plain `variable`; the injection grammar's repository is reusable for a `.Rtypes` grammar once stub files are served as documents.

Formatter (all verified):

- **Annotation formatter rewrite** (settled design, `decisions.md`): the current per-line ±1 depth walk has **no bracket matching** — the reported `}}` mis-indent and the depth leak poisoning following lines are structural, and the desired output (closers split onto own lines) is unreachable because lines are never split. New shape: join the `#:` block, parse with `type_syntax`'s real parser, pretty-print with per-bracket hug bits (opener followed by content on its line = hugged; closer mirrors its opener) honoring `indent_width`; both the expanded and the hugged style are stable; mixed input normalizes; parse failure → block left verbatim (also fixes prose corruption); drop trailing empty `#:` lines. Kills the drifted duplicate tokenizer (rejects `...` and dotted names like `data.frame`, leaving whole blocks flat).
- **Prose corruption:** `#: value < ten` → `value<ten`; `base::sum` → `base:: sum` — and fixture `double_colon_is_spaced` *blesses* the corruption (violates the never-commit-wrong-expectations rule). Fixed by parse-gating above; fix the fixture.
- **Quarto/knitr `#|` comments corrupted** to `# |` (silently breaks cell options) — add to the comment-prefix exceptions.
- **`# fmt: off` drops leading indentation** (off-mode emits from the node's first byte) and **only works at top level** (toggle lives in the PROGRAM arm only); `# fmt: skip` re-anchors the first line and breaks aligned matrices — the byte-preservation promise.
- ~25 `unreachable!()` arms keyed to grammar shape = process panics on a tree-sitter-r bump; route to the existing `FormatError::UnknownKind` path.
- Empty file becomes `\n` and is reported "reformatted".

- **Formatter follow-ups (from adversarial review):** `# fmt: skip` trailing a non-last call argument is silently ignored (the comma intervenes in the sibling check); `# fmt: off` is inert inside call-argument lists with no diagnostic for the no-op directive; expanded `@param` should support a JSDoc-style trailing description as a first-class parse (parser stores it, checker validates the name, hover can show it, formatter re-emits it verbatim) — today such blocks are simply left verbatim.

## Phase 5 — Perf honesty

- **Single parse per edit:** the engine re-parses from scratch every keystroke (the worker's incrementally-maintained tree is discarded; whole buffer re-materialized as `String` and compared). Feed the edited document/tree into the engine input.
- **Kill the k× multiplier:** `GlobalScheme(s)` runs whole-file inference once *per exported symbol* (finds one export, discards the rest). Add a per-file exported-schemes query. Also: `LoweringDiagnostics(f)` re-lowers the entire file a second time.
- **Template-clone the inference environment:** every inference rebuilds ~19 builtins + ~230 stub schemes from scratch; the oracle already builds once and clones.
- **Relative perf evidence (dev container, non-authoritative absolutes):** after the per-file exports query + template clone + single lower, per-edit recompute stays at 2 queries and the new-vs-old ratio improved ~10.6×→~131× at 281k LoC — but the absolute per-edit time on the same box rose versus the pre-semantics baseline (the slot-model flow walks, union normalization, and loop fixed points made whole-file inference genuinely more expensive). The 30 ms p50 verdict needs the CI runner's authoritative numbers; if it misses, the next lever is the residual O(N) validation walk plus inference-cost profiling of the flow model.
