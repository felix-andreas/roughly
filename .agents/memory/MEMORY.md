# Memory

Cross-session knowledge base for the agents building Roughly. Three horizons:

- **Short-term** — current focus and loose ends. Prune aggressively; delete each item once it is resolved or obvious from the tree.
- **Mid-term** — active priorities, open bugs, and technical debt. Lives across sessions until done.
- **Long-term** — durable, non-obvious design decisions and their rationale. Only things a future agent would otherwise rediscover. Keep terse and point at code or the docs.

Companion documents (kept separate only because they are larger in scope): `backlog.md` (the prioritized work punch-list), `decisions.md` (the settled architecture decision log), `typing-design.md` (open, not-yet-decided type-system design questions). Authoritative user- and contributor-facing specs live in the docs site (`docs/src/content/docs/`): `typing-reference.md` + `typing.md` (typing contract + guide), `architecture.md`, `structure.md`, `testing.md` — point at them, don't duplicate. Do not spawn new knowledge files for small things; inline them here. Every entry must be **context-free and timeless** (clear to a reader with zero project history — no milestone/phase/gate names, commit hashes, or "this session") and **high-signal** (terse; point at code/docs).

## Long-term

### Architecture

- **The analysis backend is a single in-house red-green memoized query engine** (`crates/engine`) behind the LSP server. It records each query's dependencies and recomputes only what an edit invalidates — there is no hand-maintained reverse-dependency index, dirty-set, or fingerprint table; those dissolve into recorded dependencies. It runs on a dedicated worker thread with latest-edit-wins cancellation. The `analysis` crate supplies the computational cores — parse, lower, naming, the Hindley-Milner type core, and the IDE-query layer (generic over an `IdeDatabase` fact provider) — as query bodies, plus a from-scratch `run_full` retained as the differential regression oracle and the one-shot CLI path. Detail: `architecture.md` + `crates/engine/DESIGN.md`.
- **Correctness is differential:** the engine's per-edit output is asserted byte-identical to a from-scratch rebuild over curated + randomized adversarial edit streams (well-formed *and* malformed input), and IDE-feature output is checked the same way at every cursor position. That is the regression net; there are no drift oracles (nothing is mirrored, so nothing can drift).
- **Type-notation cursor features re-lex; `SurfaceType` carries no per-node spans.** Hover/goto on a type name inside a `#:` comment and the narrowed unresolved-type error range all locate the token under a document position by *re-lexing* the annotation's own document text (`type_syntax::type_tokens_in_range` / `type_name_token_range`, built on the one `semantic_tokens` type-notation lexer, per-line `#:`-aware so multi-line blocks work). An inline `SurfaceTypeId` + parse-time span table was rejected: the parser sees a reconstructed, `#:`-stripped, re-joined buffer with no linear offset back to the document (so no single rebase base exists), and excluding an id from `SurfaceType`'s pervasive structural `Eq`/`Hash` would force hand-written impls. Re-lexing needs neither. Consequence: the engine's `prime_hover` also primes the target parse, and `prime_definition` widens to all package modules when the cursor is on an annotation type name (cross-file `@type`/`@alias` search).

### Quality bar (the acceptance contract future work is held to)

The numeric Definition-of-Done a reviewer and the CI benches must check against:
- **Performance:** keystroke-to-diagnostics p50 ≤ 30 ms / p95 ≤ 100 ms at 300k LoC; completion p95 ≤ 50 ms; no main-loop stall > 150 ms; cold-check, single-file-recheck, and IDE-feature latency budgets measured at 10k / 100k / 300k LoC.
- **Soundness:** the type relation is pure (probe-then-rollback, order-independent); nominal variance is single and correct; resolve errors are never swallowed; recursion is guarded (inference, type-syntax parser, lowering); UTF-16 position handling is correct including non-BMP characters; IDE features never panic on stale ranges.

The ignored perf/memory/fuzz benches must be gated to *these* budgets in CI, not to arbitrary thresholds.

### Engine invariants (do not break — a well-meaning refactor silently can)

- **Malformed input lowers to an empty module.** The engine's `Lower` query must short-circuit `!root_node().has_error()` → empty `Module`, matching production's suppression of diagnostics off a broken error-recovery tree; the public `lower` does *not* do this. Simplify it and the engine emits spurious naming/type diagnostics on transiently-broken keystrokes. Guarded by a malformed-input regression test (`crates/engine/tests/test_malformed_lower.rs`) and by the differential's malformed-source generator arm. Perf caveat: the empty-module short-circuit means every enter/exit of a syntactically-broken state flips the file's exports to empty and back — a cross-file invalidation storm on ordinary mid-keystroke states (unmeasured by the benches; `backlog.md` Phase 5).
- **`analysis`'s per-document interface/typecheck output maps and the package-version counter are within-run fixed-point *scratch*, not a cross-edit cache.** They are safe only because nothing drives `analysis` incrementally anymore (the server is engine-only; the CLI and the differential oracle are one-shot on a fresh `Analysis`). Do not turn them into a cache; never call `typecheck` twice on one `Analysis`.
- **The engine `validate` short-circuits on the first changed dependency**, which relies on an unenforced fetch-order invariant: a fold must fetch the membership/winner query before any per-file `Lower`, so the membership key is recorded first. Reordering fetches inside a fold body reintroduces the input-removal resurrection panic; `Parse`/`Lower` returning empty on a removed (tombstoned) input is the only backstop.
- **IDE reads must be top-level (non-recording) fetches.** Cross-file features (references / rename / symbols) avoid bleeding a coarse dependency into per-keystroke queries *only* because the IDE layer fetches outside any query body and therefore records no dependency. Never model an IDE feature *as* an engine query.
- **The interface fixed-point must not fetch an in-SCC exported-scheme key during that SCC's resolution** — it trips the accidental-cycle guard. A cooperative "is this key already computing?" check is what resolves genuine re-export / value-reference cycles (members pin to `Unknown`); the guard stays reserved for real bugs.

### Typing — durable rationale (the spec is `typing-reference.md`; this is the *why*)

- **Beta-semantics direction is settled in `decisions.md` §Beta-semantics** (mutable-slot variable model with union joins; general unions that never bind into unification variables; ordered overload sets via probe-then-rollback; `T[]` via an atomic-element constraint; parameter-position coercion policy; name-aware signature matching; strict = origins + unresolved as errors with a per-file `#: @strict` directive). Until each lands in `typing-reference.md`, the reference still describes the old semantics — the decision record wins on direction, the reference wins on current behavior.
- **HM inference with union-find variables.** A numeric constraint (`types::Constraint`) rides on unbound entries and is quantified in `TypeScheme` (`function(x) x + 1L` → `<T: numeric> fn(x: T) -> T`). A numeric var that escapes a binding without being abstracted by a function parameter defaults to `double`; defaulting is level-gated so a local inside a polymorphic function does not monomorphize the enclosing parameter.
- **Polymorphic annotations are enforced via rigid (skolem) variables.** A `<T>` binder lowers to a rigid var that refuses to bind or be constrained while the body is checked, then generalizes back to `<T>`; call sites instantiate with ordinary fresh vars.
- **Compatibility rules.** Structural (record/tuple) compatibility is covariant per field and unifies variables (so `@new` / checked annotations infer through inference-variable fields). Function types are contravariant in parameters, covariant in returns. Return position uses compatibility, not equality. `if`/`else` joins its branches: unify when possible (keeps the chooser idiom linking two inference variables), otherwise the union of the branch types; a `NULL` branch joins by pure union so it never binds an unconstrained variable to `NULL`.
- **Unions are normalized in exactly one place: `SurfaceType::union_of` / `CoreType::union_of`** (flatten, structural dedupe keeping first occurrence, `NULL` last, `Any` then `Unknown` absorb the union, singleton unwraps, empty → `NULL`). Never construct a `Union` variant literally — every builder, resolver, importer, and instantiation path re-normalizes through `union_of` because members can collapse (alias expansion, variable resolution, import-erasure to `Unknown`). Unification stays the invariant floor: set-equality for unions plus the single `T | NULL`-vs-`U | NULL` member-wise case (`nullable_single_member`); no member-matching search in unify — all directional member-wise logic lives in `check_compatibility` (actual-union = every member fits, checked before expected-union = some member fits). A union may be *bound to* an inference variable, but no union constraint is ever imposed on one (HM-speed guardrail).
- **The package interface is a bounded fixed-point.** Each round's table is the previous round's output (one propagation hop per round), so an acyclic re-export / forward-reference chain converges in ≤ (number of package globals + 1) rounds — bound the loop by global count, not document count. Re-export *cycles* are non-monotone (period-2 oscillation): a name whose rendering returns to an earlier value while differing from the previous round is on a cycle and is pinned to `Unknown`. Convergence is asserted; a genuine non-converging chain is a real defect.
- **Type-error surfacing is decoupled from the phase.** Typecheck runs lazily for the typing IDE features (hover types, inlay hints, signature help) — all on by default. Type-error *diagnostics* are gated behind `[check] typing = true` (default off); `[check] unused` gates unused-local warnings the same way; `[check] strict` flags an expression whose type is a genuine `Unknown` *origin* (first introduction of `Unknown`, tolerating `Any` and propagation — one diagnostic per root).
- **Variables are mutable slots with reaching-write flow (the R environment model).** `naming.rs` resolves every `<-`/`=` of a name in a frame to one `BindingId` slot; a single evaluation-order walk also maintains per-slot reaching-write sets (fork/join at branches, loop bodies iterated to a fixed point with binding creation made idempotent by site so re-walks mint no new ids; diagnostics emit only on a loop's final pass). Reads resolve to a slot only when a write can reach them — an unassignable slot does not shadow, so the lookup falls outward exactly like R's runtime — and warn when an unassigned path also reaches. The unused check reports **assignment sites** whose write no read reaches (code `unused`). Typecheck mirrors the model: the environment is keyed by slot, all writes funnel through an undo-log (`set_environment_entry`) so branches/loop passes/function bodies roll back without cloning the stub-laden environment, merge points join entries via `join_types` (equal keeps, one-sided keeps optimistically, different ⇒ instantiate + join as a **monotype** — schemes survive only single-write), and loops iterate entry = join(pre, out) to a fixed point (cap 3, widen still-changing slots to `Unknown`; `repeat` applies the exit state since it runs once). Package top level intentionally keeps per-site winner semantics.
- **IDE feature internals:** search-like features (workspace symbols, completion) share one subsequence / smart-case matcher with `MatchScore` ranking; S4 navigation (goto / refs / rename across `setClass` / `setGeneric` / `setMethod` / `new`, including class/generic names in string literals) is unified into one call-shape recognizer (`analysis/src/s4.rs`, used by both the outline and the navigation occurrence path); IDE features resolve through variable slots — references/rename cover all reads+writes of a slot, goto-definition and hover's "defined at" use the slot's first write.
- **One type-display policy, one renderer.** All user-facing type rendering goes through `diagnostic.rs`'s `TypeRenderer` user-facing style: inference variables display as `T`/`U`/`V` in first-occurrence order (never `?1`/`type1`), function types generalize into a `<T, U>` binder (`render_generalized_type` / `render_function_signature`), and one renderer must span everything that shares names — a whole signature, both sides of an expected/found message — because a fresh renderer restarts the numbering (the historic `lapply` bug: per-fragment renderers collapsed `list[U]` into `list[?1]`). Signature help stores parameter byte-spans into the label (`SignatureHelp.parameters`), and the server converts them to UTF-16 LSP label offsets, so parameter highlighting can never drift from the label. The fixture style (`?N`) is reserved for internal typecheck fixtures; never call `render_core_type`/`render_type_scheme` (fixture style) from a user surface. Inlay hints: function types always hint (variables generalize) unless they contain `Unknown`; other types hint only when fully concrete.

### Error handling

- **Coherence failures panic.** Document-sync / analysis-sync failures are unrecoverable and panic (in the engine worker, a panic escaping a job becomes a deterministic `process::exit(1)`); this includes the notification-path worker sends in `server.rs` (`notify`/`notify_edit`), which `panic!` rather than drop an edit. **But IDE feature lookups must never panic** — a not-yet-bound local (forward, recursive, or in an uninferred subtree) falls back to `Unknown`.

### Conventions / traps

- **Verify with CI's toolchain, not the container default.** CI uses `dtolnay/rust-toolchain@stable` = the *latest* stable; a stale container toolchain (seen: local 1.94 vs CI 1.96) has an OLDER clippy that misses newer lints (`collapsible_match`, `unnecessary_sort_by`, …) and a rustfmt that wraps differently — so `clippy -D warnings` / `fmt --all --check` pass locally yet FAIL in CI (false green, red-CI pushes). Run `rustup update stable` first and verify on that. Also: check for a *formatting diff*, not just `cargo fmt`'s exit code — piping through `| head` masks the exit via SIGPIPE.
- CI gates the workspace **except** `rofy` (needs a local R via extendr's `DEP_R_R_HOME`) and `zed_roughly` (editor/wasm toolchain) — verify locally with `--workspace --exclude rofy --exclude zed_roughly`. The active `.github/workflows/ci.yml` is scoped to the default member (`crates/roughly`); the widened whole-workspace pipeline lives in `.github/pending-ci.yml` awaiting human activation. The `rustfmt.toml` `imports_granularity`/`group_imports = One` rules are **nightly-only**; the stable toolchain CI uses skips them (with warnings), so `cargo fmt --all --check` passes on stable even where those rules would reflow imports.
- Standard-library stubs are **declaration-only `.Rtypes` files** (`crates/analysis/stubs/*.Rtypes`), NOT ordinary R. Each line is `name : <type-expr>`; the type half reuses the `#:` annotation parser (`type_syntax::parse_surface_type`), so there is no second type grammar. `stub.rs` parses the declaration layer; `stdlib.rs` harvests each declaration into a scheme and folds project overrides from `<project>/stubs/*.Rtypes` on top (project wins). The assembled `StubLibrary` is a **set-once base-environment input** — never route stub files through `did_change`. Parametric HOFs (`lapply`, `identity`, …) get real `<T> fn(...)` generics; repeating a name within one source declares an **ordered overload set** (first-accepting candidate wins at call sites; a later source replaces the whole set; end every set with an `Any` fallback — the unresolved-argument path selects the last candidate, and a set without a general fallback errors on generic wrappers); return-type-varies-by-*value* functions (`rep`, `seq`, `is`) stay `Any`. Type/class (`@type`) declarations in stub files are not yet expressible. Docs: `docs/.../stdlib-stubs.md`.
- Node-kind / field ids are hardcoded integer constants in `crates/analysis/src/tree.rs` (re-exported as `roughly::tree`). They are grammar-version-specific: bumping `tree-sitter-r` renumbers them, so every constant must be regenerated and the `node_ids`/`field_ids` pinning tests in `crates/analysis/tests/test_tree.rs` updated. Those tests guard the renumbering; a mismatch panics at runtime with "shipped stub corpus yielded no schemes" rather than mis-indexing silently.
- `formatter.md` is **generated** from `crates/roughly/tests/format/formatter.template.md` via the `documentation_examples` golden test — edit the template and run with `ROUGHLY_BLESS=1`; never edit the output file.
- The fixture harness blesses intentional expectation changes with `ROUGHLY_BLESS=1` (see `testing.md`).
- tree-sitter parses `#:` annotation comments as ordinary comments, so annotation-*syntax* errors surface only in lowering (not in the parse tree).
- The formatter emits raw string literals (`r"(...)"` / `R"[...]"`) byte-for-byte; a string node starting with `r`/`R` must not be reconstructed as `"`+content+`"`.
- **Stub-origin / project-override tests need an absolute `base_path`.** The IDE `.test` runner constructs `Analysis::new(PathBuf::new(), …)`, so `discover_project_stub_sources` resolves a relative `stubs/` against the test CWD (`crates/analysis/`), where the shipped `stubs/*.Rtypes` live — they re-harvest as "project overrides" (`namespace: None`) and shadow the shipped namespace tag. Production uses an absolute workspace root, so it doesn't arise; test stub-origin/override behavior with a temp absolute `base_path`, not a fixture.
- **UI design guideline:** no `border-l` / left-border accent rail on rounded elements (reads as generic "every other AI" design) — use a full ring, fill, underline, or weight change for selected/active states instead.
