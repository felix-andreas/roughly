## Current state

- **The analysis backend is a single in-house red-green memoized query engine** (`crates/engine`) behind the LSP server. It records each query's dependencies and recomputes only what an edit invalidates — there is no hand-maintained reverse-dependency index, dirty-set, or fingerprint table; those dissolve into recorded dependencies. It runs on a dedicated worker thread with latest-edit-wins cancellation. The `analysis` crate supplies the computational cores — parse, lower, naming, the Hindley-Milner type core, and the IDE-query layer (generic over an `IdeDatabase` fact provider) — as query bodies, plus a from-scratch `run_full` retained as the differential regression oracle and the one-shot CLI path. Architecture detail: `architecture.md` + `crates/engine/DESIGN.md`.
- **Correctness is differential:** the engine's per-edit output is asserted byte-identical to a from-scratch rebuild over curated + randomized adversarial edit streams (well-formed *and* malformed input), and IDE-feature output is checked the same way at every cursor position. That is the regression net; there are no drift oracles (nothing is mirrored, so nothing can drift).
- **Active focus: production-readiness** — the type-checker feature set is complete; the work is bringing the whole repository to release quality. Prioritized punch-list with file anchors: `backlog.md`. The standard-library **stub format** now exists (see Conventions); the remaining stub work before release is the full base/stats/utils/methods corpus and semantic-token highlighting for `.Rti`, tracked in `backlog.md`.

## Quality bar (the acceptance contract future work is held to)

The numeric Definition-of-Done a reviewer and the CI benches must check against:
- **Performance:** keystroke-to-diagnostics p50 ≤ 30 ms / p95 ≤ 100 ms at 300k LoC; completion p95 ≤ 50 ms; no main-loop stall > 150 ms; cold-check, single-file-recheck, and IDE-feature latency budgets measured at 10k / 100k / 300k LoC.
- **Soundness:** the type relation is pure (probe-then-rollback, order-independent); nominal variance is single and correct; resolve errors are never swallowed; recursion is guarded (inference, type-syntax parser, lowering); UTF-16 position handling is correct including non-BMP characters; IDE features never panic on stale ranges.

The ignored perf/memory/fuzz benches must be gated to *these* budgets in CI, not to arbitrary thresholds.

## Engine invariants (do not break — a well-meaning refactor silently can)

- **Malformed input lowers to an empty module.** The engine's `Lower` query must short-circuit `!root_node().has_error()` → empty `Module`, matching production's suppression of diagnostics off a broken error-recovery tree; the public `lower` does *not* do this. Simplify it and the engine emits spurious naming/type diagnostics on every transiently-broken keystroke — **and the differential won't catch it** (its generator is well-formed). A malformed-input regression test guards this (see `backlog.md`).
- **`analysis`'s per-document interface/typecheck output maps and the package-version counter are within-run fixed-point *scratch*, not a cross-edit cache.** They are safe only because nothing drives `analysis` incrementally anymore (the server is engine-only; the CLI and the differential oracle are one-shot on a fresh `Analysis`). Do not turn them into a cache; never call `typecheck` twice on one `Analysis`.
- **The engine `validate` short-circuits on the first changed dependency**, which relies on an unenforced fetch-order invariant: a fold must fetch the membership/winner query before any per-file `Lower`, so the membership key is recorded first. Reordering fetches inside a fold body reintroduces the input-removal resurrection panic; `Parse`/`Lower` returning empty on a removed (tombstoned) input is the only backstop.
- **IDE reads must be top-level (non-recording) fetches.** Cross-file features (references / rename / symbols) avoid bleeding a coarse dependency into per-keystroke queries *only* because the IDE layer fetches outside any query body and therefore records no dependency. Never model an IDE feature *as* an engine query.
- **The interface fixed-point must not fetch an in-SCC exported-scheme key during that SCC's resolution** — it trips the accidental-cycle guard. A cooperative "is this key already computing?" check is what resolves genuine re-export / value-reference cycles (members pin to `Unknown`); the guard stays reserved for real bugs.

## Typing — durable rationale (the spec is `typing-reference.md`; this is the *why*)

- **HM inference with union-find variables.** A numeric constraint (`types::Constraint`) rides on unbound entries and is quantified in `TypeScheme` (`function(x) x + 1L` → `<T: numeric> fn(x: T) -> T`). A numeric var that escapes a binding without being abstracted by a function parameter defaults to `double`; defaulting is level-gated so a local inside a polymorphic function does not monomorphize the enclosing parameter.
- **Polymorphic annotations are enforced via rigid (skolem) variables.** A `<T>` binder lowers to a rigid var that refuses to bind or be constrained while the body is checked, then generalizes back to `<T>`; call sites instantiate with ordinary fresh vars.
- **Compatibility rules.** Structural (record/tuple) compatibility is covariant per field and unifies variables (so `@new` / checked annotations infer through inference-variable fields). Function types are contravariant in parameters, covariant in returns. Return position uses compatibility, not equality. `if`/`else` unifies its branches.
- **The package interface is a bounded fixed-point.** Each round's table is the previous round's output (one propagation hop per round), so an acyclic re-export / forward-reference chain converges in ≤ (number of package globals + 1) rounds — bound the loop by global count, not document count. Re-export *cycles* are non-monotone (period-2 oscillation): a name whose rendering returns to an earlier value while differing from the previous round is on a cycle and is pinned to `Unknown`. Convergence is asserted; a genuine non-converging chain is a real defect.
- **Type-error surfacing is decoupled from the phase.** Typecheck runs lazily for the typing IDE features (hover types, inlay hints, signature help) — all on by default. Type-error *diagnostics* are gated behind `[check] typing = true` (default off); `[check] unused` gates unused-local warnings the same way; `[check] strict` flags an expression whose type is a genuine `Unknown` *origin* (first introduction of `Unknown`, tolerating `Any` and propagation — one diagnostic per root).
- **IDE feature internals:** search-like features (workspace symbols, completion) share one subsequence / smart-case matcher with `MatchScore` ranking; S4 navigation (goto / refs / rename across `setClass` / `setGeneric` / `setMethod` / `new`, including class/generic names in string literals) is unified into one occurrence path; unused-local detection tags bindings by kind and excludes parameters, for-loop variables, top-level/exported, and `.`/`_`-prefixed names.

## Error handling

- **Coherence failures panic.** Document-sync / analysis-sync failures are unrecoverable and panic (in the engine worker, a panic escaping a job becomes a deterministic `process::exit(1)`). **But IDE feature lookups must never panic** — a not-yet-bound local (forward, recursive, or in an uninferred subtree) falls back to `Unknown`.

## Conventions / traps

- `formatter.md` is **generated** from `crates/roughly/tests/format/formatter.template.md` via the `documentation_examples` golden test — edit the template and run with `ROUGHLY_BLESS=1`; never edit the output file.
- The fixture harness blesses intentional expectation changes with `ROUGHLY_BLESS=1` (see `testing.md`).
- `Pair` is a reserved builtin type name — do not use it in type fixtures.
- tree-sitter parses `#:` annotation comments as ordinary comments, so annotation-*syntax* errors surface only in lowering (not in the parse tree).
- The formatter emits raw string literals (`r"(...)"` / `R"[...]"`) byte-for-byte; a string node starting with `r`/`R` must not be reconstructed as `"`+content+`"`.
- CI should gate the whole workspace **except** `rofy` (needs a local R via extendr's `DEP_R_R_HOME`) and `zed_roughly` (editor/wasm toolchain) — verify locally with `--workspace --exclude rofy --exclude zed_roughly`. NOTE: the active `.github/workflows/ci.yml` is still scoped to the default member (`crates/roughly`) only; the widened pipeline lives in `.github/pending-ci.yml` awaiting human activation, because an automated session's token lacks GitHub `workflow` scope and cannot write under `.github/workflows/`. The `rustfmt.toml` `imports_granularity`/`group_imports = One` rules are **nightly-only**; the stable toolchain CI uses silently skips them, so `cargo fmt --all --check` passes on stable even where those rules would reflow imports.
- Standard-library stubs are **declaration-only `.Rti` files** (`crates/analysis/stubs/*.Rti`), NOT ordinary R. Each line is `name : <type-expr>`; the type half reuses the `#:` annotation parser (`type_syntax::parse_surface_type`), so there is no second type grammar. `stub.rs` parses the declaration layer; `stdlib.rs` harvests each declaration into a scheme and folds project overrides from `<project>/stubs/*.Rti` on top (project wins). The assembled `StubLibrary` is a **set-once base-environment input** — never route stub files through `did_change`. Parametric HOFs (`lapply`, `identity`, …) get real `<T> fn(...)` generics; only return-type-varies-by-value functions (`abs`, `rep`, `seq`, `is`) fall back to `Any`. The grammar permits repeated declarations of one name (loader is last-wins) so overload sets can be adopted later without a corpus rewrite. Type/class (`@type`) declarations in stub files are not yet expressible. Docs: `docs/.../stdlib-stubs.md`.
- Node-kind / field ids are hardcoded integer constants in `crates/analysis/src/tree.rs` (re-exported as `roughly::tree`). They are grammar-version-specific: bumping `tree-sitter-r` renumbers them, so every constant must be regenerated and the `node_ids`/`field_ids` pinning tests in `crates/analysis/tests/test_tree.rs` updated. Those tests guard the renumbering; a mismatch panics at runtime with "shipped stub corpus yielded no schemes" rather than mis-indexing silently.

## Open soundness / quality gaps

- **Type-syntax error ranges are coarse:** a `SurfaceType` carries no per-node ranges, so an unresolved-type / annotation error underlines the whole annotation instead of the offending token. Thread ranges through type-syntax parsing.
- **Nested generic-nominal arguments are treated conservatively invariant** (sound but over-restrictive); precise variance *composition* would re-admit sound nested covariant cases.
- **Structural constraints on inferred parameters are missing:** `function(x) x$name` / `x[[1L]]` / `c(x, 1L)` leak or error instead of constraining `x` to a record / indexable / atomic. Needs row/shape constraints on inference variables, analogous to the numeric constraint.
- **S4 follow-ups:** `@` slot access lowers to `Unsupported` (needs a `Slot` HIR node + lowering/typing); slots-as-class-children in the outline.
- **Tree-sitter access is string-based** (`kind()` / `child_by_field_name()`) in the `analysis` front end but id-based (`kind_id()` / `field_id()`) in `roughly`; consolidate on id-based, and dedupe the shared rope/tree helpers and the symbol indexer.
- **Diagnostic wording:** annotation-semantic errors render under `syntax-error` with a doubled `Syntax Error:` prefix; alias-cycle is not reported on unused declarations.
