# ry

**A static type checker for R**, with a language server, a formatter and a linter around it, in one
binary. It reads your source rather than running it, so it needs no R installation and answers about
code that has never been executed.

> [!NOTE]
> ry works as a standalone command-line tool or as an editor extension. It is `0.3.0-alpha`, built by
> one maintainer, and it does not need to replace what you already run — `ry fmt` and `styler` are
> happy in the same repository.

## Why ry

This started as one more R tool, and a modest one: a language server that did nothing but
go-to-definition, backed by a regex index, called *"The R(oughly good enough) language server"*. It
was fast because it barely understood anything.

Each rewrite understood more. A regex index finds a definition, and it also finds the wrong one;
parsing with tree-sitter stopped it guessing. Writing a parser for R specifically meant a syntax error
no longer stops the rest of the file being checked — and putting a type checker underneath meant it
could start disagreeing with you. The name got shorter as it went. *ry* is what is left.

Here is what the current one does. No annotations, type checking on:

```r
# billing.R
total_with_tax <- function(items, tax_rate) {
  subtotal <- 0
  for (item in items) {
    subtotal <- subtotal + item
  }
  subtotal * (1 + tax_rate)
}

total_with_tax(list(19.99, 5.00), "0.07")
```

<img src="docs/public/diagnostic.svg" alt='error[type-mismatch]: expected a numeric value (`integer` or `double`), found `character` --> billing.R:9:35' width="780">

<!-- Generated by scripts/render-diagnostic-svg.rs from a real run; that file explains why it is an image. -->

Nothing declared `tax_rate` a number. It is inferred from the arithmetic it takes part in, and the
error lands on the argument that is wrong rather than on the call.

Resolution is project-wide, so a name defined in one file is checked against its use in another:

```text
warning[unresolved]: I could not resolve `normalise_regoin` in this package, its imports, or builtins. Did you mean `normalise_region`?
 --> R/report.R:2:3
2 |   normalise_regoin(regions)
      ^^^^^^^^^^^^^^^^
```

## Getting started

- **VS Code** — the [extension](https://marketplace.visualstudio.com/items?itemName=felix-andreas.roughly)
  bundles the binary, so there is nothing else to set up. It is still published under the project's
  previous name while the rename lands.
- **A binary** — from [Releases](https://github.com/felix-andreas/roughly/releases), for CI or any other
  editor.
- **Cargo** — `cargo install --git https://github.com/felix-andreas/roughly ry-lang`.

Then, in a project directory:

```
ry check        # lint and type-check the project
ry fmt          # format it (--check and --diff for CI)
ry server       # the language server; your editor starts this for you
```

No configuration needed. Type errors are the one thing you opt into, with a `ry.toml`:

```toml
[check]
typing = true
```

For CI, `--output json` emits JSON Lines and the exit status is `0` clean, `1` findings, `2` usage
error. ry is an ordinary LSP server, so it works in any editor with LSP support; the VS Code and Zed
extensions live in this repository, and Zed's installs from
[`editors/zed`](https://github.com/felix-andreas/roughly/tree/main/editors/zed) as a dev extension until it
reaches the registry. For RStudio, ry works as an external formatter — the
[setup guide](https://ry-lang.org/installation#rstudio) has the steps.

## One analysis, four views

Formatting, linting, editor features and type checking all read the same picture of your project, so
a finding says the same thing in your editor, in CI, and on the command line.

The parser is written to recover, which means one mistake does not hide the next. Given a file with a
trailing comma, a missing comma, a wrong-arity call and a lint, R stops at the first problem and ry
reports all of them:

```text
error[trailing-comma]: Unexpected comma after last argument
error[syntax-error]: missing `,` between these arguments
error[type-mismatch]: this call supplies 1 argument, but the function requires 2 — a required argument is missing
warning[boolean-shorthand]: Use TRUE, not T, for Boolean values
```

The type error and the lint are both *after* the syntax error in the file, and both are still found.

`ry fmt` fixes spacing, indentation and bracing, and deliberately does **not** reflow your line
breaks — so a formatting run never buries a real change under rewrapped arguments:

```text
Diff in ./messy.R:
1        |-x<-c(1,2,3)
2        |-if(x>1){y<-2}
    1    |+x <- c(1, 2, 3)
    2    |+if (x > 1) { y <- 2 }
3   3    | totals <- summarise(data, by = region)
1 file would be reformatted, 0 files already formatted
```

There is also `ry repl` and `ry run`, an R console and script runner that load your system R at
runtime — the only part of the toolchain that touches R at all.

## Built for large codebases

`ry check` on real CRAN sources — package `R/` directories concatenated into single projects, with
type checking on. There is no persistent cache, so each run analyses the whole project from scratch:

| Project | Files | Lines | `ry check .` |
| --- | ---: | ---: | ---: |
| 3 packages (ggplot2, dplyr, shiny) | 414 | 101,120 | **1.96 s** |
| 6 packages (+ Matrix, survival, caret) | 711 | 174,964 | **3.29 s** |
| 18 packages (+ sf, raster, forecast, plotly, data.table, …) | 1,531 | 323,471 | **6.47 s** |

Median of five runs on a 4-core Xeon @ 2.80 GHz — a modest container, not a benchmark rig. That is
~50,000 lines per second, roughly flat as the project grows. In an editor the analysis is incremental
and only re-checks what your edit reached.

## An optional type system

Most type errors in R are found by running the code — often deep in a long script, often in front of
someone. ry looks for the ones that can be read off the source instead, before anything runs.

It cannot find all of them, and does not try. R lets you build code as it runs and change what a
variable holds halfway down a script, and no checker reads that statically. ry describes the part
that holds still — the arithmetic, the lists and records, the functions you wrote — and stays quiet
about the rest. Most of the time you write nothing at all; when you want a contract, types go in `#:`
comments, so the file is still ordinary R that R runs unchanged:

```r
#: fn(items: double[], rate: double) -> double
total_with_tax <- function(items, rate) sum(items) * (1 + rate)
```

The inference runs whether or not you turn type errors on. Hover, completion, signature help and
inlay hints all read inferred types; `typing = true` only decides whether mismatches are *reported*.

Two things are deliberately missing: **class hierarchies**, and **overloading in your own code** —
give a parameter a union type, or split the function. Both are omitted to keep checking fast, because
the inference is Hindley–Milner, which is provably sound and close to linear on real code; type
systems that allow those features can spend a long time on a single expression, and an editor cannot
afford that.

Full R compatibility is not the goal. Code with a describable shape gets checked, and everything else
becomes `Unknown`, which is compatible with everything — so a gap means a check was skipped, not that
a wrong answer was produced.
[Limitations](https://ry-lang.org/type-checking/limitations/) is the honest accounting of what is
missing, data frames most of all, and
[concepts](https://ry-lang.org/type-checking/concepts/) is the gentler way into the rest.
